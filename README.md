# GlowCleanWin

Проверка и лечение домашнего ПК с Windows 10/11 одним скриптом PowerShell. Сначала он только читает и показывает, что хорошо, а что плохо. Потом один раз спрашивает, что исправить.

> **In English.** A single Windows PowerShell 5.1 script that audits a home Windows 10/11 PC: updates, Defender, certificate stores, browsers, hosts/proxy/DNS, autoruns, accounts, preinstalled apps and telemetry settings. It prints a colour-coded report and then asks once what to fix. Every change is backed up and journaled. The interface is in Russian. A special focus is on trusted root certificates that are not part of the Microsoft and Mozilla trust programs and allow HTTPS interception.

## Зачем

Скрипт вырос из ручной уборки одного ПК: десяток одноразовых скриптов «собрать автозапуск», «посмотреть сертификаты», «выключить рекламу Windows» слились в один, который можно принести на флешке на любой домашний компьютер и запустить двойным щелчком.

Главный вопрос, на который он отвечает: **нет ли в доверенных хранилищах постороннего корневого сертификата**, владелец которого может незаметно подменять HTTPS-сайты. Остальные проверки отвечают на вопрос «что ещё на этом компьютере не так».

## Запуск

1. Скачать `GlowCleanWin.ps1` и `GlowCleanWin.cmd` в одну папку.
2. Двойной щелчок по `GlowCleanWin.cmd`. Права администратора скрипт запросит сам.
3. Подождать 2–5 минут, прочитать итог.
4. На вопрос «что исправить» в первый раз ответить Enter — ничего не изменится.

То же из консоли:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:\Tools\GlowCleanWin.ps1"
```

| Параметр | Что делает |
| --- | --- |
| `-ReportOnly` | только отчёт, без вопроса об исправлении |
| `-SkipUpdates` | не искать неустановленные обновления (самая долгая часть) |
| `-Demo` | показать вывод на выдуманных данных, ничего не проверяя и не меняя |

Нужен Windows PowerShell 5.1 (он встроен в Windows 10 и 11). Из PowerShell 7 скрипт сам перезапустится в 5.1.

## Что исправляет и как

В конце один вопрос:

| Ответ | Что будет исправлено |
| --- | --- |
| `YES` | всё красное, у чего есть автоисправление |
| `ALL` | красное и жёлтое |
| `1 4 7`, `3-6`, `YES 12 15` | пункты с этими номерами |
| Enter | ничего |

Правила, по которым скрипт меняет систему:

- **Только после ответа.** До вопроса скрипт ничего не пишет, кроме своего отчёта.
- **«Только по номеру».** Так помечены пункты, где скрипт не может сам отличить вредное от настроенного владельцем: свои сценарии в автозапуске, незнакомые корневые сертификаты, локальный прокси, сторонние приложения. `YES` и `ALL` их не трогают.
- **Непонятный ответ отменяет всё.** `not all` или `yes?` — ничего не меняется.
- **Точка восстановления** создаётся перед первой правкой.
- **Копия перед изменением.** Удаляемый сертификат сохраняется как `.cer`, старое значение реестра — в `registry_before.tsv`, файл и задача планировщика — копией в `backup`.
- **Журнал.** Каждое изменение дописывается в `<компьютер>_changes.tsv`.
- **Повторная проверка.** После правок все проверки запускаются ещё раз, и итог показывается заново.

Удаление корневого сертификата имеет цену: сайты, которые работают только на нём, начнут показывать предупреждение в браузере. Копия сертификата сохраняется, вернуть его можно в два щелчка.

## Что остаётся после запуска

Рядом со скриптом появляется папка `GlowCleanWin_Reports`:

```text
GlowCleanWin_Reports\
  <компьютер>_<дата>\report.txt     отчёт
  <компьютер>_<дата>\backup\        копии изменённого
  <компьютер>_changes.tsv           журнал изменений
  <компьютер>_ignore.txt            свой список «это нормально» (создаётся вручную)
```

В `report.txt` не попадают командные строки целиком, значения реестра и содержимое файлов: длинные строки, пароли и токены в аргументах заменяются на `[скрыто]`. Отчёт можно показывать другим. Журнал и `backup` хранят старые значения целиком — их показывать не стоит.

В `<компьютер>_ignore.txt` можно записать по одной строке кусок заголовка пункта, который на этом компьютере нормален (например, `Tailscale`). Такие пункты станут серой справкой.

## Какие сертификаты считаются посторонними

- **Вне программ доверия.** Корневые сертификаты, которых нет в списках Microsoft и Mozilla, но которые массово ставят вручную по чьей-то инструкции. Скрипт узнаёт их по списку внутри себя: в списке лежат не имена, а SHA-256 от имени сертификата. Свой добавляется одной строкой (`Get-NameHash 'Имя сертификата'`).
- **От программ, вскрывающих HTTPS.** Антивирусы и отладочные прокси ставят собственный корневой сертификат. Пока программа установлена, это справка; если программы уже нет, а сертификат остался — красное.
- **Незнакомые.** Всё остальное в хранилище доверенных корневых, что не принадлежит известным центрам сертификации. Жёлтое, удаление только по номеру.

## Ограничения

- Интерфейс только на русском.
- Сертификаты пользователей проверяются у тех, кто вошёл в систему в момент запуска.
- Посторонний корневой сертификат с неприметным именем в хранилище сторонних корневых (AuthRoot) скрипт не распознает: там он ищет только сертификаты из своего списка и известные программы перехвата HTTPS.
- Это не антивирус. Скрипт смотрит на настройки и точки автозапуска, файлы на вирусы проверяет Defender.
- Часть красного исправляется только вручную (старая Windows, больной диск, неподписанная служба) — в отчёте написано, что делать.
- Настройки приватности записываются как политики, поэтому в Параметрах и в Edge местами появляется надпись «управляется организацией».
- Скрипт запускается с правами администратора и поставляется без гарантий: первый запуск на новом компьютере — всегда без исправлений.

## Проверено

- **Синтаксис Windows PowerShell 5.1:** `tools/Check-Syntax.ps1` разбирает файл парсером и запрещает конструкции PowerShell 7; `tools/Lint.ps1` сверяет имена параметров в вызовах своих функций и ищет чтение переменных, которым ничего не присвоено.
- **Модульные тесты:** `tests/Unit.ps1`, проверок: 68 — разбор командных строк и путей, правила риска, `hosts`, регулярные выражения сертификатов, разбор записи сертификата из реестра, разбор ответа пользователя, маскировка секретов.
- **Полный прогон на имитации Windows:** `tests/MockWindows.ps1` подменяет реестр, Defender, планировщик, службы, пользователей и Appx и гоняет весь путь «проверка → исправление → повторная проверка» на «грязном» и «чистом» компьютере.
- **Независимое ревью кода** перед первым запуском (отдельным ИИ-агентом, который не видел, как писался скрипт): 18 замечаний, исправления — в истории коммитов (`fix(review): …`).
- **На реальной Windows:** Windows 11 Pro 25H2, сборка 26200.9550, 03.10.2026 — два прогона, все проверки отработали без ошибок, каждый прогон занял меньше двух минут. Первый выявил ложные срабатывания (коммит `fix: findings from the first run on real Windows`), второй подтвердил исправления. Режим исправления на реальной системе пока не применялся.

## Тесты

Тесты идут под PowerShell 7 на любой системе, Windows для них не нужна:

```sh
pwsh tools/Check-Syntax.ps1
pwsh tools/Lint.ps1
pwsh tests/Unit.ps1
pwsh tests/MockWindows.ps1 -Answers ALL    # «грязный» ПК, исправить всё
pwsh tests/MockWindows.ps1 -Clean          # «чистый» ПК
```

`MockWindows.ps1` ничего не утверждает сам: он печатает тот же вывод, что увидит пользователь, и его читают глазами.
